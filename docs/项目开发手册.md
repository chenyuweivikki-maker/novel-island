## 三、核心链路

### 对话 → 项目自动提取（重要）
```
首页/创作页对话回复完成 → _sync_chat_to_kb / _sync_project_chat_to_kb
  → 取该会话 synced=0 的用户消息（最近 3 条、≥8 字）
  → ingest_material → build 状态机（清洗分块 → 并行抽取实体/关系/事件/章节摘要
    → 图谱一致性检查 → 入库图谱+向量+TF-IDF）→ 标记 synced=1
```
- 人设/关系自动长进「人设卡片」「人物关系图」；创作页只作用于当前项目
- 书名同步：规则提取《书名》/「书名定为X」→ 更新 novels.title；兜底书名用 LLM 总结（仅 title_auto=1 时）
- 时间线/章纲只跟正文（章节事件带 chapter_id 才进时间线）

### 记忆四层（PRD）
1. 工作记忆：LangGraph State
2. 短期记忆：chat_history + 摘要压缩（6 轮触发，保留 2 轮）
3. 长期记忆：图谱 + 向量 + TF-IDF
4. 程序性记忆：前端 👍/👎、润色采纳/放弃 → procedural.db → 灵感/剧情推荐注入偏好

## 五、关键设计决策（勿随意改）

1. **覆盖策略**：persona 键级覆盖，冲突只提示不阻断（作者说了算）
2. **未发送消息不进列表**：发消息瞬间才 ensure 建会话；输入框草稿存 localStorage
3. **归档 = 软标记**：chat_history.archived=1，数据保留可恢复，列表底部「归档」分组
4. **增量入库防重**：chat_history.synced 标记；短消息（<8字）不入库；每轮最多 3 条
5. **精确属性检索短路**：命中直接返回、不写记忆（设计如此，非 bug）
6. **首页行为**：点「首页」重置为吉祥物欢迎页（清空消息区）；点左侧会话才显示内容；底部文案「你写作的时候，我会一直在」
7. **主题**：黑白极简；选中态=浅灰底（surface-2）+ 深色文字（勿改回黑底，用户明确要求）

- **#page-chat 曾有无条件 display:flex** → 对话框永远显示、其他 tab 页面被盖住（"tab 失灵"根因）。对话页默认必须 display:none
- **general_opening_fallback 曾被调用但从未定义** → LLM 失败兜底路径二次崩溃，已补
- **创作页流式对话曾不写记忆**（generate() 缺 add_turn）→ 已补
- ~~CSS/JS 不走 no-store~~ → **已修（08-21）：HTML/JS/CSS 全部 no-store，改后无需强刷**（无头测试用全新 context 天然无此问题）
- **无头测试要查 computed style/截图**，只查 class/display 会漏掉视觉回归（尖角 bug 就是这样漏的）
- **readlines() 编辑文件时换行符叠加** → 每行变双空行；用 read().split('\n') 再 join
- **LangGraph 节点未注册就 set_entry_point** → ValueError: Found edge starting at unknown node
