## 〇.5、开发协作规范（所有 Agent 必读）

> 详细版见同目录 **`开发协作规范.md`**（含「哪块↔哪些文件」模块地图）。下面是硬性约定，改动前先读。

1. **只改点名的那块**：需求方指定业务域，只动该域文件，改前先列「将改文件清单」。
2. **跨界先声明**：须跨模块（如前后端都要改）时先说明影响面，同意后再动。

6. **可回溯**：每次改完给「改了什么 / 为什么 / 怎么验证」三行。
7. **逻辑改动带验证**：业务逻辑用隔离单测或对着运行服务实测后再交付。

## 三、核心链路

### 对话 → 项目自动提取（重要）
```
首页/创作页对话回复完成 → _sync_chat_to_kb / _sync_project_chat_to_kb
  → 取该会话 synced=0 的用户消息（最近 3 条、≥8 字）
  → ingest_material → build 状态机（清洗分块 → 并行抽取实体/关系/事件/章节摘要
    → 图谱一致性检查 → 入库图谱+向量+TF-IDF）→ 标记 synced=1
```
- 人设/关系自动长进「人设卡片」「人物关系图」；创作页只作用于当前项目
- 书名同步：规则提取《书名》/「书名定为X」→ 更新 novels.title；兜底书名用 LLM 总结（仅 title_auto=1 时）
- 时间线/章纲只跟正文（章节事件带 chapter_id 才进时间线）

### 记忆四层（PRD）
1. 工作记忆：LangGraph State
2. 短期记忆：chat_history + 摘要压缩（6 轮触发，保留 2 轮）
3. 长期记忆：图谱 + 向量 + TF-IDF
4. 程序性记忆：前端 👍/👎、润色采纳/放弃 → procedural.db → 灵感/剧情推荐注入偏好

## 五、关键设计决策（勿随意改）

1. **对话 = 项目记忆唯一来源，映射不编造**：入库只取作者对话原话，抽取的实体名/属性/关系须有原文证据——`_is_entity_name`（名字逐字出现+非停用词）、`_sanitize_attrs`（属性有原文线索）、关系双方名字逐字出现、`auto_book` 不向入库文本注入"主要角色"提示。**目的是防 LLM 脑补**：聊天聊到什么才映射什么，作者之后自己看、自己改、自己写正文。**改动任何抽取逻辑务必保留这套硬校验，不要绕过**。
2. **覆盖策略**：persona 键级覆盖，冲突只提示不阻断（作者说了算）
3. **未发送消息不进列表**：发消息瞬间才 ensure 建会话；输入框草稿存 localStorage
4. **归档 = 软标记**：chat_history.archived=1，数据保留可恢复，列表底部「归档」分组
5. **增量入库防重**：chat_history.synced 标记；短消息（<8字）不入库；每轮最多 3 条
6. **精确属性检索短路**：命中直接返回、不写记忆（设计如此，非 bug）
7. **首页行为**：点「首页」重置为吉祥物欢迎页（清空消息区）；点左侧会话才显示内容；底部文案「你写作的时候，我会一直在」
8. **主题**：黑白极简；选中态=浅灰底（surface-2）+ 深色文字（勿改回黑底，用户明确要求）
