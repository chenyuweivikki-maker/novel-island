# 小说岛 — 面试技术要点

> 用 8 个里程碑讲清楚一个完整 Agent 系统。每个里程碑 = 一个核心概念 + 一个能讲的实战点。

## 一句话概括项目

基于 LangGraph 状态机的中文网文创作 Agent，解决作者"人设崩塌、记忆断层、逻辑矛盾"问题。
覆盖：建库（并行抽取）→ 问答（意图路由→工具调用→质检→记忆）→ 图谱（关系查询）→ 成本控制。

## 里程碑 1：状态机（地基）

**概念**：State（全局背包）→ Node（读写背包的函数）→ Graph（节点连线图）。

**面试话术**：
> 我整个系统基于 LangGraph 状态机。所有节点共享一个 NovelIslandState，节点间不传参、只读写同一个背包。
> 相比直接调函数，状态机的价值是：①可观测（每一步读写哪个字段一目了然）②可插拔（加节点只加边，不动其他）
> ③可分支（条件边让流程能分流、打回）。

**实战证明**：把 `ask` 接口从顺序代码改成 `qa_app.invoke({...})`，一行调用跑完整流程。

## 里程碑 2：意图路由（条件分支）

**概念**：`add_conditional_edges(节点, 路由函数, 路径表)`——路由函数读 State 返回节点名，LangGraph 查路径表分流。

**面试话术**：
> 我有 IntentRouterNode，根据问题关键词判断意图（fact_qa/inspiration），用条件边分流到不同处理节点。
> 先用规则（关键词）判断——便宜、可解释、零延迟；以后升级 LLM 分类只改这一个节点，图结构不动。

## 里程碑 3：工具调用（agent 的分水岭）

**概念**：LLM 看到工具清单 → 自主决定调用 → 代码执行 → 结果回填 → 最终回答。执行权在代码，决策权在 LLM。

**面试话术**：
> 我让 LLM 自主决定是否调 search_kb 工具检索知识库。实测它对"沈屿是谁"会主动发起 tool_call(query=沈屿)，
> 而不是直接编答案。工具定义是 JSON Schema（name/description/parameters），描述写得好 LLM 才正确调用。
> 执行函数放在 TOOL_EXECUTORS 映射表，LLM 永不直接碰数据库，安全可控。

## 里程碑 4：防幻觉质检（差异化亮点）

**概念**：LLM-as-Judge——同一模型扮演"作者"（生成）和"编辑"（质检），质检不过打回重试（循环回边），有重试上限。

**面试话术**：
> 我设计 HallucinationCriticNode，让 LLM 检查回答的每条事实是否都有原文依据，输出 JSON(pass/issues)。
> 质检不过就通过条件边打回 agent 重新生成，最多重试 2 次防死循环。实测抓出过"江观南是房东"的关系错误，
> 重试后修正为"唐嘉措才是房东"。
> **诚实补充**：质检是最后防线不是万能药。如果检索片段本身有误导性，生成和质检看到同一份问题依据，
> 重试仍可能重复错。这让我意识到质检质量依赖检索质量，所以质检放在检索之后。

## 里程碑 5：并行建库（工程能力）

**概念**：并行分支 + 汇合。build → [实体抽取, 事件抽取, 关系抽取] 三路并行 → 汇合输出。

**面试话术**：
> 建库流程状态机化，实体/事件/关系抽取三路并行，汇合点等所有分支完成才输出。
> 踩过一个坑：并行分支同时写同一字段（current_step）会报 InvalidUpdateError——并行节点必须只写自己独占的字段。
> 这个经验说明状态机对"哪些字段可以并发写"有明确约束。

## 里程碑 6：三层记忆（PRD 记忆系统落地）

**概念**：工作记忆（State）→ 短期记忆（对话历史）→ 长期记忆（知识库）。短期超长自动摘要压缩。

**面试话术**：
> 三层记忆：工作记忆是 LangGraph State，短期记忆是对话历史（会话内），长期记忆是知识库（永久）。
> 短期记忆超 6 轮自动交给 LLM 压成摘要，只留最近几轮——这是成本控制的关键（PRD 对话历史摘要）。
> 实测第 2 轮问"她的大结局"能正确知道"她"指上一轮的江观南——多轮上下文衔接上了。
> 踩坑：messages 必须以 system 开头（OpenAI 协议），否则 LLM 会陷入工具循环。

## 里程碑 7：模型路由 + 成本（工程严谨性）

**概念**：任务分级（simple/main/complex）→ 选模型。每次调用记录 model/token/成本。

**面试话术**：
> 我的模型路由是配置驱动的：MODEL_ROUTES 表按任务级别选模型，加新模型只改配置不改代码。
> 成本记录每次调用的 token 和估算成本，有汇总接口。实测单次问答约 0.013 元。
> 这为 PRD 的成本监控看板提供了数据基础。

## 里程碑 8：知识图谱（差异化亮点）

**概念**：实体→节点，关系→边。查询：邻居（直接关系）+ 路径（多跳推理）。内存实现 + JSON 持久化。

**面试话术**：
> 图谱建在实体抽取之上：LLM 抽关系三元组（source, relation, target），存入图谱。
> 核心查询是 query_path（BFS 多跳推理）——回答"两实体怎么关联"，这是向量检索做不到的。
> 存储层做了抽象：先用内存+JSON 持久化跑通形态，接口不变的情况下以后可换 Neo4j。

## 整体架构亮点（串联讲）

1. **可插拔**：加节点/分支/工具只加配置和边，不动核心代码（8 个里程碑都是增量加，没重构）
2. **成本意识**：模型路由 + 对话摘要 + 质检重试上限，三层成本控制
3. **质量保障**：质检在检索后、输出前，LLM-as-Judge + 循环重试
4. **真实测试**：用真实小说《观南嘉措》资料测试，发现检索召回、关系抽取噪声等真实问题

## 面试问题预判

**Q：为什么用状态机不用直接调函数？**
A：可观测、可插拔、可分支。加质检节点只加边，不动其他。

**Q：你的 agent 怎么防幻觉？**
A：检索后质检，LLM-as-Judge 查"回答有无原文依据"，不过打回重试。但诚实说质检依赖检索质量。

**Q：怎么控制成本？**
A：三级模型路由（简单任务便宜模型）+ 对话摘要压缩 + 质检重试上限。

**Q：知识图谱比向量检索强在哪？**
A：关系查询（谁和谁什么关系）、多跳推理（路径发现），向量检索只能语义匹配。
