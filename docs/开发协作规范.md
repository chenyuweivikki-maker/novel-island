# 小说岛 · 开发协作规范

> **本文件是后续所有 Agent / 开发者在本仓库工作的共同约定。**
> 任何一次改动都必须遵守这里的边界与流程；与「开发记忆.md」配套阅读。
> 建立时间：2026-08-24

---

## 1. 目标

- 让**任何接手本项目的人/Agent**，看完这份规范就知道"改哪个需求应该动哪些文件、别越界、怎么验证"。
- 让开发像正常产品一样：**分层、单一职责、变更有边界、数据不擅动、走 git、可回溯**。

## 3. 协作规则（必守）

1. **只改点名的那块**：需求方指定业务域后，只动该域文件；改动前先列出「将改文件清单」。
2. **跨界先声明**：若一项改动必须跨模块（如新功能要前后端），先说明影响面，得到同意再动。
3. **数据不擅动**：清库、删项目、改用户数据等，默认**不执行**，必须需求方书面确认。做数据类操作前先备份。
4. **走 git**：改动独立、聚焦提交；大改动用分支。
5. **配置与密钥**：统一走 `.env`，代码里不硬编码口令/密钥。
6. **可回溯**：每次改完给三行——「改了什么 / 为什么 / 怎么验证」。
7. **逻辑改动带验证**：涉及业务逻辑时，用隔离单测或对着运行中的服务实测后再交付。

## 4. 前端 vs 后端 边界

- **纯前端**改动（页面/样式/页面 JS）：只动 `frontend/public/`，后端尽可能不动。
- **纯后端**改动（接口/业务/存储）：只动 `backend/app/`，前端不动。
- **须前后端配合**（如新接口 + 新页面）：拆开分步做，先后端（立好接口）再前端（接接口），两步各自验证。

## 4.1 前端设计基准 = Figma（重要）

- **前端一切 UI 以 `figma/`（Figma 导出规范）与 `小说岛_UI页面清单与信息架构.md` 为设计基准**，按图开发，不自行发挥主题/布局。
- 设计规范：黑白极简、大气留白、温暖陪伴；桌面 Web 优先（规范内容宽 1171px）。
- **首页/着陆页**：按 Figma 版为准（已确认没问题），不作为改动目标；若要在首页动刀，先对照 Figma 确认差异再改。
- 手机适配/动效等非规范内容，先与需求方确认再实现。

## 5. 数据与代码分离

- **代码**：可随时改、走 git。
- **数据**（`backend/data/` 下的 db / json / npz）：预生产或用户创作内容，**任何改动都要确认**；删除前先备份到 `data/` 之外。

## 6. 文档规范

- 本文件和 `docs/开发记忆.md` 是项目事实源；改完重要逻辑后，在「开发记忆」里补一条开发日志。
- 遇到"哪块归谁"不确定时，以本文模块地图为准，或回到对话确认边界后再动手。
